
[[[ CWXEditor ]]]

[ これは何？ ]

　XML形式のCardWirthデータを作成するエディタのDによる実装です。
　何気なくクラシックなCardWirthシナリオも編集できたりしますが、あくまで
おまけなので新規作成はできません。


[ インストール/アンインストール ]

　以前のバージョンだとCWPyに寄生していましたが、今は別の場所に置けます。
初回起動時にCWPyエンジンの場所を指定してあげれば大丈夫。
　CWPyが無くても一応動きますが、XML形式のシナリオを編集する際にカードの
背景が出なかったりします。
　アンインストールの時はcwxeditorのフォルダを丸ごと消してください。
　まったく　かんたん　だ！


[ 起動オプション ]

　クリックだの何だので普通に起動しますが、何気なくコマンドラインオプションを
付けられるようになってます。

使い方: cwxeditor [-help | -ini <PATH> | <OpenID ...>] <SCENARIO> [<CWXPath ...>]
オプション:
  -help        起動オプションの説明を表示して終了します。
               (GUIアプリケーションとしてコンパイルすると上手く
               表示できないみたい……)
  -ini <PATH>  指定されたパスの初期化ファイルを使用します。
  <SCENARIO>   起動と同時に指定されたシナリオを開きます。
               (*.wsn/Summary.xml/Summary.wsm/[フォルダ])
OpenID:
	-a <ID>    シナリオを開いた後、<ID>で指定したIDのエリアを開きます。
	-b <ID>    シナリオを開いた後、<ID>で指定したIDのバトルを開きます。
	-p <ID>    シナリオを開いた後、<ID>で指定したIDのパッケージを開きます。

オプション:
	*/Summary.xml  指定されたSummary.xmlを読込み、シナリオを開きます。
	*.wsn          指定されたwsnファイルを展開し、シナリオを開きます。
OpenID:
	-a <ID>        シナリオを開いた後、<ID>で指定したIDのエリアを開きます。
	-b <ID>        シナリオを開いた後、<ID>で指定したIDのバトルを開きます。
	-p <ID>        シナリオを開いた後、<ID>で指定したIDのパッケージを開きます。
CWXPath:
	<CWXPath>      シナリオを開いた後、<CWXPath>で指定したリソースを開きます。
	               詳しくは後述。


[CWXPathについて]

　CWXEditorで開いたシナリオの各エリア・フラグ・コンテント等のリソースには
全て、統一書式のパスが割り振られます。以下のようなものです

 - battle:id:2
 - castcard:8/beastcard:0/event:0
 - area:3/event:0/:5/:1

　これが何を意味しているのかというと……

battle:id:2
	ID:2のバトル
castcard:8/beastcard:0/event:0
	8番目のキャスト
	 - が持つ0番目の召喚獣カード
	  - の下にある0番目のイベントツリー
area:3/event:0/:5/:1
	3番目のエリア
	 - の下にある0番目のイベントツリー
	  - の下にある0番目のスタートコンテント
	   - の下にある5番目のコンテント
	    - の下にある1番目のコンテント

　という感じです。番号は0から始まる事になっています。また、エリア等のIDを
持つリソースであれば":id"と記述する事によってIDを指定できます。
　リソースの種類毎に"area"や"castcard"のように名前がついてますが、イベント
コンテントなどは冗長になるので"名前無し"になっていたりします。
　以下にリソース名の一覧を示しておきます:

　area       .... エリア
　battle     .... バトル
　package    .... パッケージ

　castcard   .... キャストカード
　skillcard  .... スキルカード
　itemcard   .... アイテムカード
　beastcard  .... 召喚獣カード
　infocard   .... 情報カード

　menucard   .... エリアに配置されるカード
　enemycard  .... バトルに配置されるカード

　event      .... イベントツリー

　variable   .... 状態変数(フラグ・ステップ)のルート
　flag       .... フラグ
　step       .... ステップ
　dir        .... 状態変数のサブディレクトリ


[ 保留事項 ]

・CWPyで変換したシナリオを見ると、シナリオにタグやラベルを付けられるように
　なっているようなのですが、具体的にどうすればいいのか分からないので、
　今は対応してません。
　タグは何となく分かるのですが、ラベルが。


[ 欠陥 ]

・重い。
・Win2000では動かない。
・どう考えてもWin98系列でも動かない。

　実行ファイルが巨大だった件は、どうにかこうにかUPX圧縮に成功したので何とか
なりました。元ネタと同じくらいなら文句ないでしょう。文句ないよね。ね？
　処理の重さについては、特にエリアを開いた際に大量の画像を読込む場合、シナ
リオのロード、セーブの部分で顕著です。しかしデータ形式が変わったからある意味
仕方ない所。努力はします。
　三番目はDWTがWindows 2000を切ってるらしくてお手上げになってしまいました。
Win98系列は試してないけどどう考えても無理だと思った。


[ 完成後の展望 ]

　というものを以前に公開した版では載せていたんですが、やっぱり人それぞれ
望むものはあるし、CWPy側の動向もあるし、やっぱりどうしよう、消しといた方が
いいかな、ええいいいや残しとけ。というわけで、

 * 以下の文章は古くなっています *

　このCWXEditorには夢があるッ！
　エディタで実装するのは簡単だけどエンジン側でも対応して貰わなければ意味が
ないアイデアがいくつかあります。
　ただし新しいアイデアに手をつけるのはエディタの機能を一通り実装してから。

・カード名とシナリオ名に何文字でも使えるようにする。描画時に幅を縮めれば行ける。
　しかしキャストカード等の名前はメッセージコンテントに現れる関係上制限が必要。
・カード名の無いカードのちゃんとした実装。要は名称表示部を削りたいのです。
　現在のCardWirthでは名無しのカードは存在できない(一見名無しのカードは名前欄に
　空白が入っている)ので、互換性的には問題ないはず。
・本物のラウンド終了イベントと毎ラウンドイベント。
・背景描画速度とかを一時的に固定する。理想主義的には全てのシナリオがユーザ好みの
　設定でプレイできるべきだが、Readmeに「これこれこういう設定でプレイしてね」と
　書かざるを得ない、固定しないと成り立たないシナリオが存在するという現実。
・スキル等でBGMや背景とかを変更した後、元に戻したりする。
・防御修正を一時的に操作して元に戻す効果。竜殺しみたいな。防御修正以外はあっても
　意味無い……よね？
・PCを宿へ戻す。人数限定シナリオは作りやすくはなるけど、さて必要か？
・他諸々。

　難度とかは考慮せずに思いつくまま列挙してます。
　というかCWPyを作っているのは私ではないので……うん、ごめんなさい、自重する。
